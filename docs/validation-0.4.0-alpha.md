# 0.4.0-alpha: content correctness and incremental compilation

This release keeps the existing TL2026 executables / locked Ubuntu TL2023 package profile. It does not silently upgrade LaTeX, fonts, biblatex or Biber: changing those can change pagination and bibliography output. The release manifests now identify both the engine version and the exact package-lock digest. Select a different immutable TDS explicitly when reproducing another installation.

## Changes

- `latexmk` returns `complete` and structured `diagnostics`. Missing characters, missing index/glossary outputs, substituted font shapes, missing hyphenation patterns and unresolved references are visible even when TeX exits zero. Set `strict: true` to make these diagnostics fail `success`. Existing success semantics are preserved when strict mode is omitted.
- Convergence covers every chapter `.aux`, table of contents, list of figures/tables, bookmarks and Beamer navigation. Oscillating states stop with `cycleDetected`; pass exhaustion remains separately reported.
- All named `.idx` jobs run, as do makeindex-based glossaries and acronym lists with the generated `.ist`, input/output and transcript extensions. Xindy/bib2gls are host integrations, not silently substituted with makeindex.
- BibTeX reruns for bibliography-control changes, including chapter aux files, rather than for page-label-only changes.
- The showcase uses strict incremental sessions and shows content diagnostics directly.
- `createCompileSession` serializes edits and keeps engine/helper workers alive within the configured LRU memory limit. It reuses validated control state; changed file sets, assets, preambles, includes, environment or resource identity invalidate it. Derived bibliography/index/glossary results are discarded on source changes. Failed or incomplete compilations do not populate the cache. Repeated identical content may reuse helper outputs.
- Runtime startup overlaps independent WASM/glue/ICU/format loading with TDS unpacking. Backend reads use bounded concurrency. Filesystem path encodings and `ls-R` are cached across fresh instances and invalidated when resources are fetched. Engine instances remain fresh because TeX globals are not reentrant.
- Fontconfig caches join luaotfload caches across runs. Positive ICU initialization errors now fail explicitly; negative warnings remain accepted. Missing-file retries avoid re-fetching loaded files and repeat misses within a run.
- `processEnv` sets real libc variables before TeX starts, including `SOURCE_DATE_EPOCH` and `FORCE_SOURCE_DATE`. Existing `env` retains its kpathsea-override meaning. Use matching v0.4+ engine artifacts for this option; old artifacts fail explicitly.
- Both `pdflatex.fmt` and `latex.fmt` are generated by the matching WASM executable. The DVI-oriented `latex.fmt` remains available in full TDS but no longer inflates the minimal pdfLaTeX core.
- Full TDS retains contributed biblatex styles that were previously deleted. Their individual hashes are included in the published manifest.

## Optional resource packs

`resource-packs.json` publishes the version, compressed size and SHA-256 of each pack. Configure `EngineConfig.resourcePacks` with `{url, sha256}` entries. Base files win on conflicts; packs add files without replacing the base format. Pass the same font packs to XeTeX and its `xdvipdfmx` helper. Node accepts local paths as well as file/HTTP URLs.

- `texmf-pack-portuguese.tar.gz`: Portuguese babel/hyphenation resources and the locked publisher collection, including abntex2 and its satellites needed by the minimal core. Portuguese patterns are also preloaded in the regenerated formats.
- `texmf-pack-multilingual.tar.gz`: Arabic/CJK language packages, Noto core/CJK and Amiri fonts. This is an optional **Unicode Xe/LuaLaTeX profile with explicit fonts**, not a distribution of the legacy CJK metric/VF engines. Select Noto via fontspec; a Unicode engine alone does not supply a font covering every character. Emoji/color-font coverage is not universal.

The packs retain package copyright notices. They are kept separate from the core, bounded by the same decompression limits, and verified before unpacking. CLI defaults omit these optional large archives; download explicitly with `--assets texmf-pack-portuguese,resource-packs.json` (or multilingual). The CLI keeps pack archives separate rather than overlaying the unpacked base TDS.

## Application integration

```ts
import { createCompileSession } from '@typeward/texlive-wasm';

const base = new URL('/texlive-wasm/', location.href);
const catalog = await fetch(new URL('resource-packs.json', base)).then(r => r.json());
const pt = catalog.packs.portuguese;
const session = createCompileSession({
  resourceVersion: '0.4.0-alpha/pinned-tds',
  maxLiveEngines: 2, // choose 1 on memory-constrained devices
  config: id => ({
    enginePath: new URL(`${id}/emscripten/${id}.wasm`, base).href,
    ...(id === 'biber'
      ? { bundleUrl: new URL('biber/emscripten/biber-vfs.tar.gz', base).href }
      : {
          manifestUrl: new URL('tex-packages-pdflatex.json', base).href,
          resourcePacks: [{ url: new URL(pt.url, base).href, sha256: pt.sha256 }],
        }),
  }),
});

const result = await session.compile({
  engine: 'pdflatex',
  mainTex: 'main.tex',
  files: [{ path: 'main.tex', content: source }],
  strict: true,
  timeoutMs: 120_000,
});
// Show result.diagnostics; only publish result.pdf if result.success.
// On closing the project:
await session.dispose();
```

For Xe/LuaLaTeX choose their corresponding core manifests; XeTeX also needs `icuDataUrl`. Configure Biber's own VFS digest for cross-origin delivery. Changing the external TDS/fonts requires disposing and creating a session with the new configuration; `clear()` only clears incremental project state. A session serves one project and does not share auxiliary files across applications.

`tools(context)` is an explicit host integration point, called in `before`, `auxiliary` and `after` phases. It receives the current files and remaining deadline/cancellation signal, and returns generated files. `auxiliary` outputs participate in another TeX pass until they stabilize. Hosts can supply SVG/EPS conversion, cached highlighting, xindy/bib2gls or external PDF validation without enabling shell escape inside WASM. The host must honor the supplied deadline/signal for its own processes. An error thrown by a validator rejects the pipeline. There is no automatic browser-side installation of Ghostscript, Pygments or veraPDF, and no blanket PDF/A/PDF/UA conformance claim.

## Validation and reproduction

- `npm run check`: formatting, TypeScript, coverage gates, packaged Node worker smoke and native Rust tests.
- `npm run test:browser`: worker/storage/cancellation tests in Chromium, Firefox, WebKit and mobile profiles.
- `node scripts/smoke-all.mjs`: real engines and bibliography/CSL regressions.
- `node scripts/smoke-quality.mjs`: Portuguese/ABNT, named indexes, glossary/acronyms, actual reproducible year, missing-glyph strict rejection, Noto CJK/Arabic shaping and rebuilt DVI format. Requires dist, built bundles/packs and Poppler.
- The quality smoke checks the deterministic two-page PDF against the native reference SHA-256 `20319d511ca5b404001435144b7f3ae93238f212b8bcb616c090502fe91c1405` from the previous controlled comparison. The release workflow runs this gate before uploading bundles.
- `node scripts/benchmark-session.mjs <output.json>` compares six revisions with a clean compile, requiring identical PDF hashes. It records pass counts and durations, including the cold first session compilation separately.

Measurements are exploratory Linux/Node measurements, not guarantees for mobile WebViews. No optimization flags or threading defaults were changed without a controlled engine-level speed/size comparison. The existing single-threaded `-Oz` build remains the mobile-compatible default.

Final local results: **205 TypeScript tests**, **91.42% line coverage** (gates unchanged), **53 native Rust tests**, **15 browser tests**, **8 engine/bibliography smokes**, and the nine content/fidelity checks in `smoke-quality.mjs`. The incremental benchmark measured 207 ms versus 376 ms median on warm edits (45% reduction) with identical PDFs. pdfLaTeX core is 21.34 MiB gzip. Full compilations did not improve uniformly across all engines; see [raw measurements and limits](analysis/0.4.0-alpha/README.md).
